# 全球动态再平衡系统（DAA）核心架构指引

> 核心目标：将“再平衡算法”与“人因评价”深度耦合，形成可演进、可审计、可隔离风险的量化管理体系。

## 一、系统核心哲学

### 1) 数学底线
- 通过动态再平衡维持资产配置不偏离风险边界。
- 把触发阈值、目标权重、订单规模约束为可计算的确定性规则。

### 2) 智慧过滤
- 引入人因模型（分析师准确率/纪律性/风控能力/透明度）对资产权重进行加权。
- 让本金优先流向“高手一致性高”的资产，自动抑制“噪声共识”。

### 3) 风险隔离
- 通过 Max In/Out、流动性上限、标签隔离舱将风险物理封装。
- 对高风险标签（例如 `sb`）资产执行“只减不增”硬约束。

## 二、四层一体化架构

### L1 数据感知层（Sensory Layer）
- 跨市场持仓归一：A/H/US/加密资产统一估值口径。
- 情报融合：客观因子（价格/动量/估值）+ 主观因子（观点/预期/情绪）。
- 流动性画像：记录每个资产 24h 可交易名义规模，用于订单上限计算。

### L2 策略计算层（Strategy Layer）
- 再平衡内核：目标权重 + 当前持仓 + 价格 -> 建议订单。
- 动态触发阈值：
  - 默认 5%
  - 强势持仓（趋势强 + 人因高分）提升至 10%
- 结果要求：输出订单、触发解释、漂移摘要。

### L3 人因过滤层（Human-Factor Layer）
- 人因评分卡：准确率、风控、纪律、透明度四因子加权。
- 价值陷阱识别：当“观点强烈但走势背离”达到阈值时，自动降级或隔离。
- 流派去重：识别同风格信息源过度集中，避免“看似分散、实则同质”。

### L4 风控执行层（Guardrail Layer）
- Tag 权限控制：高/中/低风险池配仓上限，`sb` 资产禁止新增买入。
- Max In/Out 硬约束：单笔调仓不得超过
  - 总资产的 `X%`（默认 10%）
  - 该资产流动性的 `15%`
- 执行结果分层：可执行订单 / 被拦截订单 / 拦截原因。

## 三、模块落地与代码映射（本次重构）

### 1) 统一决策引擎
- 文件：`src/daa/unifiedRebalanceV1.ts`
- 关键能力：
  - 一次请求完成四层处理
  - 人因加权后再进入再平衡内核
  - 风险隔离与 Max In/Out 后置裁剪

### 2) 统一 API
- 文件：`app/api/daa/rebalance/unified/route.ts`
- 路由：`POST /api/daa/rebalance/unified`
- 权限：强制账号密码登录后的会话鉴权（viewer 及以上）

### 3) 统一工作台（UI）
- 文件：`app/daa/dashboard/_components/DaaDashboardPageClient.tsx` + `app/daa/dashboard/_tabs/DaaConsoleTab.tsx`
- 入口：`/daa/dashboard`
- 能力：
  - 粘贴 JSON 快照
  - 一键接入 yfinance / 雪球 / Twitter 做实时同步
  - 调整触发阈值
  - 查看执行摘要、隔离清单、原始响应

### 4) 统一输入主存储（Storage Backbone）
- 文件：`app/daa/unifiedInputStore.ts`
- 主 Key：`daa.unified.input.v1`
- 说明：
  - 所有运行态输入统一写入该 key
  - 启动时自动清理历史 legacy key

### 5) 登录约束统一化
- 文件：`middleware.ts`
- 变更：`/daa/*` 页面除 `/daa/login` 外全部要求会话登录。

## 四、演进路线（建议）

1. **阶段 A：策略可信化**
   - 将人因评分与真实交易后验表现闭环联动（自动校准）。
2. **阶段 B：风险精细化**
   - 引入资产相关性、集中度约束、跨币种 FX 压力测试。
3. **阶段 C：执行同步自动化（非自动下单）**
   - 强化人工执行回填、审计追踪与异常回滚，不接入自动下单。
4. **阶段 D：自进化能力**
   - 建立“决策质量评分 -> 参数漂移建议 -> 灰度发布”机制。
