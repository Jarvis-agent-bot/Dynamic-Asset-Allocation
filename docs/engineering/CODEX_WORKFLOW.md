# Codex 协作工作流（DAA）

## 1. 适用范围

用于 DAA 仓库内所有需求分析、开发实现、评审验收场景，默认采用“文档先行 + 小步快跑 + 可回归验证”。

## 2. 标准流程

1. 需求输入：明确目标、边界、成功标准。
2. 方案计划：先输出可执行计划，再进入实现。
3. 文档更新：先更新架构/工程文档，再改代码。
4. 代码实现：按 Phase 拆分最小可交付。
5. 回归验证：执行测试、类型检查、构建检查。
6. 评审合并：记录影响、风险、回滚方案。

## 3. 任务输入模板（给 Codex）

```md
## 背景
## 目标
## 不做什么
## 约束（时间/技术/兼容）
## 验收标准
## 相关文件/模块
```

## 4. Plan 输出模板（由 Codex 生成）

```md
# 标题
## 摘要
## 变更清单（文件/接口/类型）
## 实现步骤
## 测试方案
## 风险与回滚
## 假设与默认值
```

## 5. 实现前检查（Pre-Implementation Gate）

- 相关文档是否为 `Accepted`。
- 是否存在冲突需求或过时接口。
- 是否明确 API 输入输出和错误码。
- 是否明确迁移步骤和兼容策略。

## 6. PR 描述模板

```md
## 目标
## 变更范围
## 关键实现点
## 测试结果
## 风险与回滚
## 文档同步
```

## 7. 回归验证基线

与仓库脚本保持一致：

```bash
pnpm test
pnpm run typecheck
pnpm run build:check
```

## 8. 发布前检查模板

- 功能开关/配置是否就绪。
- DB migration 是否可重复执行。
- Cron 与通知是否已验证退避策略。
- 监控告警与日志字段是否齐全。

## 9. 文档同步要求

以下任一变更必须更新文档：

- 新增/修改 API。
- 新增 DB 表或字段。
- 风控阈值、策略参数变化。
- 调度频率与数据源变更。

## 10. 失败处理与降级

- 外部数据源异常：降级到缓存/上次快照，并标注数据时效。
- 通知渠道异常：记录失败日志，不阻断主流程。
- 回测归因失败：返回基础绩效指标并给出缺失原因。
