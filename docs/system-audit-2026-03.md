## 二、严肃评价（按模块）

### 2.1 再平衡流程：碎片化、无闭环

**现状**：再平衡逻辑分散在三个触发点（手动/定时/漂移），但它们之间没有统一的"再平衡周期"概念。用户点击"运行建议"后得到一堆建议单，然后逐条或批量执行。执行完没有复盘报告。

**致命问题**：
1. **无审批环节**：生成建议后直接可执行，对于大额再平衡（涉及全组合权重调整）极其危险
2. **无 Basket Order**：不能把多条建议打包成一个"再平衡批次"，执行后也无法追溯"这批属于同一次再平衡"
3. **触发条件互相独立**：drift-check cron 和 daily-analysis cron 各自运行，可能在同一天触发两次冲突的建议
4. **无冷静期实现**：虽然 cooldownHours 参数存在，但 cron 之间不共享状态

**改造建议**：
```
引入"再平衡周期"(Rebalance Cycle) 实体：
  - 每次触发创建一个 cycle，状态: draft → pending_approval → executing → completed / cancelled
  - draft 阶段可调整建议、增删订单
  - pending_approval 阶段需要确认（手动模式）或等待窗口期（自动模式）
  - 执行阶段逐条执行并记录进度
  - 完成后生成复盘报告（PnL 影响、漂移修正程度）
```

### 2.2 资产加入流程：功能存在但体验差

**现状**：用户通过搜索框搜索 yfinance，找到资产后点击加入观察列表。Featured Assets 提供了推荐列表。

**问题**：
1. **无分类浏览**：不能按"美股 / 港股 / A 股"、"ETF / 个股 / 债券"浏览
2. **加入后无引导**：加入观察列表后，用户需要手动设置目标权重、手动加入再平衡列表
3. **无批量操作**：不能一次加入多个资产
4. **搜索结果信息不足**：只有 symbol/name/price，缺少市值、行业、历史表现等关键筛选信息

**改造建议**：
```
1. 增加资产浏览器(Asset Browser)：按市场→资产类别→行业 三级分类
2. 加入向导(Add to Portfolio Wizard)：搜索 → 确认信息 → 设置目标权重 → 加入篮子
3. 支持从模型组合导入：提供预设的全球配置模板（60/40、全天候、永久组合等）
4. 批量导入：从 CSV 或其他来源批量导入资产列表
```

### 2.3 再平衡模式：自动与手动的边界模糊

**现状**：`rebalanceConfig.mode` 支持 "auto" 和 "manual"，但实际上 auto 模式只是 cron 定时运行建议生成 + 发邮件，并不会自动执行交易。

**问题**：
1. **"自动"名不副实**：自动模式只生成建议，不自动执行
2. **缺乏半自动模式**：比如"自动生成建议，但小额调整自动执行，大额需确认"
3. **无频率控制**：自动模式没有"每周/每月/每季"的频率选项
4. **无市场时段感知**：不知道当前是否是交易时段

**改造建议**：
```
三级自动化：
  - Manual: 所有操作手动触发
  - Semi-Auto: 漂移 > 阈值时自动生成建议，推送审批；小于 NAV 1% 的调整自动执行
  - Full-Auto: 自动生成 + 自动执行（需设置严格的安全阈值）

加入频率控制：
  - 漂移触发频率: 每日检查 / 每周检查
  - 定期再平衡: 每月 / 每季度 / 自定义
  - 市场时段: 仅在目标市场开盘时执行
```

### 2.4 风险控制：有骨架无血肉

**现状**：策略配置中有 maxDrawdownPct、perAssetStopLossPct、maxConcentrationPct 等参数，但它们只在决策引擎的建议生成阶段被"软参考"。

**致命问题**：
1. **执行阶段无风控**：用户手动下单时不检查任何风控限制。可以把 100% 资金买入单一资产
2. **无实时监控**：没有仪表盘展示当前组合的风险指标（波动率、VaR、最大回撤等）
3. **止损是纸面功能**：perAssetStopLossPct 存在但没有任何代码检查当前持仓是否触及止损线
4. **无相关性检查**：correlationCapPct 存在但从未在执行路径中使用

**改造建议**：
```
1. Pre-Trade Risk Check: 每笔订单执行前强制检查
   - 执行后是否超过 maxPositionPct?
   - 执行后组合集中度是否超标?
   - 当天交易金额是否超过 maxOrderPctOfNav?

2. 实时风险仪表盘:
   - 当前组合波动率
   - 当前最大回撤（从峰值计算）
   - 每个持仓的 PnL%（vs 止损线）
   - 资产相关性热力图

3. 自动止损:
   - 当持仓浮亏 > perAssetStopLossPct 时触发告警
   - 当组合回撤 > maxDrawdownPct 时触发紧急通知
   - 可配置是否自动减仓

4. 风险预算:
   - 引入 risk budget 概念
   - 每个资产类别有独立的风险预算
   - 超预算时阻止新增头寸
```

### 2.5 回测系统：孤岛效应严重

**现状**：策略实验室有 5 种策略的回测和 Ensemble 优化，但完全独立于实际投资流程。

**问题**：
1. **参数不同步**：回测用的参数和实际再平衡用的参数是两套
2. **无法"应用"**：优化出来的最优权重无法一键应用到实际篮子
3. **无真实性**：不考虑交易成本、滑点、资金容量
4. **无比较**：不能"我的实际表现 vs 如果用了回测最优策略"

**改造建议**：
```
1. 参数统一: 回测参数从实际策略配置读取，而非独立维护
2. 一键应用: 回测优化结果 → 一键 "Apply to Portfolio" → 更新目标权重
3. 虚拟组合: 可创建多个虚拟组合，各自跑不同策略，对比表现
4. 回测增强:
   - 加入交易成本模型（固定费率 + 滑点估算）
   - Walk-forward 验证（训练期 + 验证期交替）
   - 蒙特卡洛模拟（置信区间）
5. 归因分析: 实际 vs 基准 vs 最优策略的 PnL 归因
```

### 2.7 基金经理持仓的角色

**现状**：人因模块通过丹券 API 采集基金经理持仓，生成 aggregatedScore、conviction、thesisDrift 等信号。这些信号在 unifiedRebalanceV1 中被用于决策引擎的人因层。

**问题**：
1. **不可见**：工作台完全看不到人因信号，用户必须切到人因中心页面
2. **不可操作**：信号影响了建议生成，但用户不知道"这条 BUY 建议是因为基金经理共识"
3. **不可追踪**：基金经理的持仓变化（加仓/减仓/清仓）没有变更通知
4. **不可定制**：用户无法调整人因信号在决策中的权重

**改造建议**：
```
1. 工作台集成:
   - 在资产表格中增加"人因评分"列
   - 鼠标悬停显示信号来源（哪些基金持有、权重变化）
   - 建议单中标注"人因信号贡献度"

2. 变更通知:
   - 当基金经理大幅加仓（conviction 上升 >10%），推送通知
   - 当基金经理清仓（conviction → 0），触发风险警告
   - 当共识翻转（从 bullish → bearish），触发审查

3. 权重可配:
   - 在策略配置中暴露人因信号权重（当前硬编码）
   - 允许"仅参考"模式（信号展示但不影响决策）

4. 共识对比视图:
   - "基金经理持有但我没有" → 发现机会
   - "我持有但基金经理都卖了" → 风险警示
   - "基金经理都在加仓的" → 强共识信号
```

## 六、总结

这个系统已经具备了一个完整的资产配置系统的核心骨架：资产发现、持仓管理、再平衡决策、策略回测、外部信号集成。但它目前的主要问题是：

1. **碎片化**：功能分散在 5 个页面，彼此不互通
2. **风控空转**：风控参数存在但不执行
3. **孤岛效应**：回测、人因都是独立模块，不回流到主流程
4. **缺乏闭环**：没有"触发 → 审批 → 执行 → 复盘"的完整周期

核心改造方向是：**把它从"5 个独立工具的合集"变成"一个有完整工作流的投资管理系统"**。
