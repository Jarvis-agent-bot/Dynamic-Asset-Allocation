# DAA 工作台体验改造白名单（V1）

## 1. 目标（产品经理口径）

- 降低操盘手从“看到机会”到“确认执行”的认知时间。
- 降低误操作与重复点击，提升执行确定感。
- 在不改后端协议的前提下，优先优化核心决策路径。

---

## 2. 改造白名单（允许动）

### 0. 流程可运行前置（P0 门禁）
- 登录后 3 秒内完成基础健康探测（`/api/daa/workbench/bootstrap`、`/api/daa/workbench/rebalance/cycles`）。
- 出现后端异常时，前端只展示业务可理解文案，不透出 SQL/堆栈原文。
- 工作台加载失败时提供“重试 + 前往交易记录 + 查看帮助”三联 CTA，而不是仅保留空白主区。

### A. 信息表达（只改前端 UI）
- 资产状态标签：持仓 / 观察 / 候选池（颜色 + 文案 + 图标）。
- BUY/SELL/HOLD 建议的层级视觉（行底色、角标、排序）。
- 关键指标格式统一（金额、百分比、小数位、千分位）。

### B. 路径效率（不改接口契约）
- 搜索结果增加“加入观察”“直接入池(默认5%)”双入口。
- 再平衡流程顶部增加进度条/步骤状态（生成→预览→执行）。
- 执行后增加页面内回执卡（非仅 Toast）。

### C. 异步与反馈（前端状态管理）
- 工作台/总览首屏骨架屏，减少布局跳动。
- 洞察加载分阶段提示（已取数/AI解读中/完成）。
- 所有执行按钮统一 loading 锁与防重入文案。

### D. 错误与空状态（前端提示策略）
- 用户错误 vs 系统错误分层展示（Inline + Toast）。
- 搜索无结果提供下一步建议（示例关键词）。
- 首次无持仓 onboarding 引导（3 步 CTA）。

### E. 可访问性与响应式（样式层）
- 关键按钮点击区提高到最小 44px。
- 颜色语义补充图标/文字（非纯颜色依赖）。
- 1280px 下确保“建议表 + 执行区”首屏完整可读。

---

## 3. 改造黑名单（本轮不动）

- 不改后端 API 路由、字段、权限模型。
- 不改交易执行引擎与风控计算逻辑。
- 不引入新状态管理库。
- 不做大规模路由重构（例如拆分工作台为多页）。

---

## 4. P0 改造包（建议先做）

1. 资产状态 Chip + 建议行优先级样式。
2. 执行确认弹窗后的“执行回执卡”常驻展示。
3. 搜索结果“双按钮入口”（加入观察/加入候选池）。
4. 首屏骨架（总览 + 工作台）与统一 loading 文案。
5. 关键操作按钮高度统一到 `h-11`。

---

## 5. 完整流程走查脚本（截图验收）

请按顺序执行并截图，文件名建议 `01~12`：

1. 进入 `/daa/dashboard`（首屏加载态）。
2. 总览加载完成（指标卡 + 图表 + CTA）。
3. 进入 `/daa/dashboard/workbench` 默认 Tab。
4. 资产发现：搜索关键词并得到结果。
5. 从搜索结果加入观察/候选池。
6. 观察列表查看状态区分（持仓/观察/候选）。
7. 调整目标权重并保存。
8. 生成/刷新建议。
9. 勾选建议并查看风控区。
10. 打开“确认执行”弹窗（含执行摘要）。
11. 执行后回执（成功/部分成功/失败）。
12. 跳转交易记录页，核对周期与订单。

---

## 6. 我将按这 5 个 PM 维度给你评分

- 决策清晰度：是否 3 秒内看懂“现在该做什么”。
- 路径效率：从搜索到可执行建议的点击成本。
- 执行确定性：执行前预期与执行后回执一致性。
- 容错与恢复：报错后能否快速回到主流程。
- 高频可用性：长时间使用是否低认知负担。

---

## 7. 本轮目标指标（建议）

- 从“搜索资产”到“进入候选池” <= 2 步。
- 从“生成建议”到“执行确认” <= 90 秒。
- 重复点击执行按钮导致重复下单 = 0。
- 首屏加载跳动明显投诉 = 0。
