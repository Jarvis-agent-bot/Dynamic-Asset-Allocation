# DAA v2 系统设计文档

> 全球多资产动态再平衡系统 · 重构设计
> 设计原则：**简单、直觉、闭环**

---

## 一、设计哲学

### 第一性原理

一个组合管理者每天做的事情只有四件：

```
看 → 想 → 做 → 查
│     │     │     │
│     │     │     └── 4. 查看结果（交易记录、PnL、周期复盘）
│     │     └──────── 3. 执行操作（下单、再平衡、加减仓）
│     └────────────── 2. 研究决策（发现资产、分析信号、生成建议）
└──────────────────── 1. 查看状态（组合健康度、权益变动、风险指标）
```

系统的每个页面应精确对应其中一个环节。不多，不少。

### 设计约束

1. **一个用户、一个组合**（暂不考虑多组合）
2. **模拟交易**（不对接真实券商）
3. **自动=自动生成建议+通知，不自动执行**
4. **中文为主，代码/变量用英文**
5. **不做回测**（策略实验室暂移除，待成熟后回引）

## 二、页面架构

### 四页结构

```
侧边栏导航：
┌─────────────────────┐
│  DAA                │
│                     │
│  📊 总览            │  ← 看：组合状态一目了然
│  💼 工作台          │  ← 想+做：资产管理、再平衡
│  📋 交易记录        │  ← 查：订单历史、再平衡周期
│  ⚙️ 设置            │  ← 配：策略、风控、数据源
│                     │
│  ─────────────────  │
│  主题切换 │ 用户菜单 │
└─────────────────────┘
```

| 页面 | 路由 | 职责 | 对应原页面 |
|------|------|------|-----------|
| 总览 | `/daa/dashboard` | 只读状态面板 | 资产首页（重构） |
| 工作台 | `/daa/dashboard/workbench` | 核心操作面板 | 工作台+人因中心（合并重构） |
| 交易记录 | `/daa/dashboard/trades` | 审计与复盘 | 新增 |
| 设置 | `/daa/dashboard/settings` | 系统配置 | 设置（重构） |

**删除的页面：**
- ~~策略实验室~~ → 暂移除，回测功能待成熟后以独立模块回引
- ~~人因中心~~ → 信号内联到工作台，基金池管理移到设置

3. **资金流水**保留在总览页（入金/出金是低频操作，不需要在工作台）
4. **无表格**：总览页不展示持仓明细表格（那是工作台的事）

## 五、再平衡系统设计

### 5.1 两种触发策略

```
┌─────────────────────────────────────────────────┐
│              再平衡触发引擎                       │
│                                                 │
│   ┌──────────────┐    ┌──────────────┐         │
│   │ 定期再平衡    │    │ 偏移量再平衡  │         │
│   │              │    │              │         │
│   │ 频率:        │    │ 阈值: 5%     │         │
│   │  每月/每季   │    │ 检查: 每日   │         │
│   │  每半年/每年 │    │              │         │
│   │              │    │ 任一资产的    │         │
│   │ 到期日自动   │    │ |实际-目标|   │         │
│   │ 生成建议     │    │ > 阈值时触发  │         │
│   └──────┬───────┘    └──────┬───────┘         │
│          │                   │                  │
│          ▼                   ▼                  │
│   ┌──────────────────────────────────┐         │
│   │ 冷静期检查                       │         │
│   │ 上次再平衡距今 > 冷静期？         │         │
│   │                                  │         │
│   │ 是 → 创建再平衡周期              │         │
│   │ 否 → 跳过，记录日志              │         │
│   └──────────────────────────────────┘         │
│                                                 │
│   ┌──────────────┐                              │
│   │ 手动触发      │  ← 用户随时可点击            │
│   │ 不受冷静期限制│     忽略冷静期                │
│   └──────┬───────┘                              │
│          │                                      │
│          ▼                                      │
│   创建再平衡周期 (Rebalance Cycle)              │
└─────────────────────────────────────────────────┘
```

**两种策略可以同时启用**，互不排斥：
- 例："每季度强制再平衡，但如果中间任一资产偏移 > 10%，也触发"
- 冷静期同时约束两种触发（手动触发除外）

### 5.2 再平衡周期 (Rebalance Cycle)

每次触发都会创建一个**再平衡周期**，它是一个有状态的实体：

```
状态流转:

  ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
  │ 已生成    │────→│ 审阅中    │────→│ 执行中    │────→│ 已完成    │
  │ generated │     │ reviewing │     │ executing │     │ completed │
  └──────────┘     └─────┬─────┘     └──────────┘     └──────────┘
                         │
                         ▼
                   ┌──────────┐
                   │ 已取消    │
                   │ cancelled │
                   └──────────┘
```

**数据模型：**

```typescript
interface RebalanceCycleV1 {
  cycleId: string;                    // 唯一标识
  status: "generated" | "reviewing" | "executing" | "completed" | "cancelled";
  triggerSource: "calendar" | "drift" | "manual";
  triggerReason: string;              // e.g., "AAPL 偏移 7.2% 超过阈值 5%"

  // 快照（生成时记录）
  snapshotAt: string;                 // 生成时间
  equitySnapshot: number;             // 生成时总权益
  driftSnapshot: Array<{              // 每个资产的偏移快照
    symbol: string;
    actualPct: number;
    targetPct: number;
    driftPct: number;
  }>;

  // 建议
  proposals: Array<{
    assetKey: string;
    symbol: string;
    side: "BUY" | "SELL";
    suggestedQty: number;
    suggestedNotional: number;
    price: number;
    reason: string;
    selected: boolean;                // 用户是否选中执行
  }>;

  // 风控检查结果
  riskCheck: {
    passed: boolean;
    items: Array<{
      rule: string;
      status: "pass" | "warn" | "block";
      message: string;
    }>;
  };

  // 执行结果（执行后填充）
  executedAt?: string;
  executedOrders: string[];           // trade_ticket IDs
  executionSummary?: {
    ordersExecuted: number;
    ordersFailed: number;
    totalNotional: number;
    newMaxDriftPct: number;           // 执行后最大偏移
  };

  // 用户操作
  cancelledAt?: string;
  cancelReason?: string;
  notes?: string;
}
```

### 5.3 执行流程

```
用户点击 [生成再平衡建议]
  │
  ▼
系统运行 rebalanceCore()
  ├── 读取当前持仓、价格、目标权重
  ├── 计算偏移、生成订单
  ├── 运行风控检查 (pre-trade risk check)
  ├── (可选) LLM 二次分析
  └── 创建 RebalanceCycle，状态 = generated
  │
  ▼
展示建议列表 + 风控结果
  ├── 用户可勾选/取消个别建议
  ├── 用户可查看每笔建议的理由
  ├── 用户可添加备注
  └── 状态 → reviewing
  │
  ▼
用户点击 [执行选中] 或 [执行全部]
  ├── 弹出确认对话框（摘要：N 笔交易、总金额、风控状态）
  ├── 用户确认 → 状态 → executing
  ├── 逐笔执行 → 创建 trade_ticket
  ├── 全部完成 → 状态 → completed
  └── 记录执行摘要

或用户点击 [取消本次再平衡]
  └── 状态 → cancelled，记录原因
```

### 5.4 风控检查 (Pre-Trade Risk Check)

**在建议生成时和执行前各检查一次：**

```typescript
interface PreTradeRiskCheck {
  items: Array<{
    rule: "max_position"        // 执行后单一持仓是否超过上限
         | "max_order_pct"      // 单日交易是否超过 NAV 占比上限
         | "concentration"      // 执行后组合集中度
         | "stop_loss_breach"   // 执行后是否有持仓在止损线以下
         | "total_weight"       // 目标权重总和是否 ≤ 100%
    status: "pass" | "warn" | "block";
    current: number;
    limit: number;
    message: string;
  }>;

  overallStatus: "pass" | "warn" | "block";
  // block = 阻止执行（硬约束）
  // warn = 允许执行但显示警告（软约束）
  // pass = 全部通过
}
```

**规则详情：**

| 规则 | 类型 | 说明 |
|------|------|------|
| max_position | block | 单一持仓不得超过 maxPositionPct (默认 30%) |
| max_order_pct | warn | 单日交易金额不得超过 NAV × maxOrderPctOfNav (默认 10%) |
| concentration | warn | HHI 集中度检查 |
| stop_loss_breach | warn | 如果某持仓已浮亏超过 perAssetStopLossPct |
| total_weight | block | 篮子目标权重总和不得超过 100% |
