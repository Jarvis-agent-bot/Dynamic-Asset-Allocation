# DAA 全权大脑设计（阶段一）

## 目标

把当前分散的三套能力收敛成一个统一大脑：

1. **Chat 助手**：面向用户的交互入口
2. **Cognitive Agent**：定时/事件驱动的研究与复盘引擎
3. **执行与设置系统**：调仓、模拟交易、配置、通知

目标不是“无门禁裸执行”，而是：

- **认知上全局可见**
- **规划上统一编排**
- **执行上可授权分层**
- **复盘上闭环学习**

这才是适合投资系统的“全权大脑”。

## 现状问题

### 1. 脑和手是分裂的

- Chat 助手能回答部分问题，也能触发部分模拟动作
- Cognitive Agent 能做调查、生成 briefing、积累 thesis / memory
- 但两者不是同一个 orchestration plane

结果就是：

- 用户感觉 Chat 不像真正大脑
- Agent 做过的事情，Chat 不一定知道怎么调用
- 工具与权限模型不统一

### 2. 能力可见性不足

当前系统里，很多能力其实已经存在：

- 活跃论点
- Agent 日报
- 多模型路由
- 研究工具注册表
- 调仓增强器

但 Chat 默认没有把这些作为“主能力”暴露给用户。

### 3. 权限模型过于硬切

当前更像：

- 只读查询
- 少量动作
- 高风险动作确认

但缺少一层明确的 **大脑权限分级**。

## 目标架构

建议把系统收敛成五层。

### A. Context Plane（全局上下文层）

统一提供：

- 组合状态
- 市场状态
- 最新调仓周期
- 活跃 thesis
- Agent briefing
- 会话记忆
- 学习摘要
- 系统配置
- LLM 路由
- 工具目录
- 运行健康状态

### B. Planning Plane（规划层）

唯一入口：**Brain Orchestrator**

负责：

- 意图识别
- 任务分解
- 决定走 Chat 回复 / 工具调用 / Agent 调查 / 执行动作
- 为不同任务选择 `analysis` / `decision` / `research` 模型

### C. Action Plane（动作层）

统一抽象为 Brain Actions：

- 查询类：组合、市场、风险、论点、briefing
- 调查类：运行认知循环、初始化 thesis
- 策略类：生成调仓建议、生成配置建议
- 执行类：模拟交易、模拟调仓执行
- 配置类：改系统参数、改模型路由、改通知策略

### D. Policy Plane（策略门禁层）

全权大脑不等于无限直写。

建议引入 3 档模式：

1. **Advisor**
   - 只读 + 建议
   - 不执行写入

2. **Operator**
   - 允许运行认知循环
   - 允许初始化 thesis
   - 允许生成建议
   - 模拟交易 / 模拟调仓仍需确认

3. **Autopilot**
   - 对预授权动作直接执行
   - 高风险动作仍需确认或由风控阻断
   - Agent 只能输出目标权重计划，不能自动修改系统配置

### E. Review Plane（复盘层）

所有关键动作都必须回写：

- 做了什么
- 为什么做
- 用了哪些工具
- 结果怎样
- 是否改善 thesis / config / execution

## 本次已落地的阶段一

本次代码已经把 Chat 往“大脑入口”推进了一步：

### 已新增

- `brain_status`：查询大脑当前能力、模型路由、认知链路、动作边界
- `agent_run`：从聊天入口手动触发一轮 Cognitive Agent
- `agent_bootstrap`：从聊天入口初始化当前持仓论点

### 已统一

- Chat 能看到系统 LLM 路由摘要
- Chat 能看到工具注册表能力规模
- Chat 能看到当前活跃 thesis 与最新 Agent 运行状态

### 仍保留门禁

- 模拟交易 / 模拟调仓执行：保留确认
- 真实交易：不支持
- 密钥明文读取：不支持
- 配置直改：不开放给 Agent

## 本次继续补充的控制面

为了让“全权大脑”不只停留在文案层，这次又补了一层正式控制面：

- 设置页新增 **大脑与自动化**
- 引入 `brain.mode`
  - `advisor`
  - `operator`
  - `autopilot`
- 把以下能力改成按授权等级生效：
  - 运行认知循环
  - 初始化 thesis
  - 模拟交易 / 模拟调仓
  - Autopilot 下按目标权重计划触发本地模拟调仓

当前默认推荐：

- **Operator** 作为人工协作模式
- **Autopilot** 作为事件驱动模式，但权限边界固定为目标权重计划 + 统一风控 + 本地执行网关

## 下一阶段建议

### 阶段二：统一 Brain Action Bus

把这些动作统一成一个动作总线：

- `run_agent_cycle`
- `bootstrap_theses`
- `generate_rebalance`
- `execute_rebalance_sim`
- `execute_trade_sim`

Chat / Agent / UI 都走同一层。

### 阶段三：自动调仓审计面

让每次自动调仓都能回答：

- 哪个事件触发了 Agent
- 本轮目标权重计划是什么
- 哪些 intent 被接受或跳过
- 生成了哪些提案
- 哪条风控规则允许或阻断了执行
- 通知是否成功送达

### 阶段四：事件驱动脑

让大脑不只被动响应聊天，而是主动响应事件：

- 市场 regime 变化
- 新新闻进入
- 组合权重大幅偏移
- 某 thesis 长期未复盘
- 连续多次执行失败

### 阶段五：Autopilot

只有在以下条件同时满足时再开：

- 动作总线统一
- 策略门禁稳定
- 审批规则明确定义
- 复盘链路完整
- 回滚机制可用

## 结论

一个合理的“全权大脑”应该是：

- **认知上全局可见**
- **规划上统一调度**
- **执行上分级授权**
- **结果上持续学习**

而不是简单把确认按钮删掉。
